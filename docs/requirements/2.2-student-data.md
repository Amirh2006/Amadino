# Phase 2.2 — Required Student Data

## Goal
Define the exact student data fields, validation rules, and financial tracking attributes required by Amadino, including dual mobile numbers (Mobile 1, Mobile 2), Total Tuition, and Current Debt.

---

## 1. Entity: Student

| Field | Type | Required | Constraints | Description |
|-------|------|----------|-------------|-------------|
| id | Integer | Yes | Primary key, auto-generated | Unique student identifier |
| fullName | String | Yes | Non-empty, max 100 chars | Student's full name |
| fatherName | String | Yes | Non-empty, max 100 chars | Father/guardian name |
| nationalId | String | No | Unique if provided, max 20 chars | National ID / birth certificate number |
| grade | String | Yes | Non-empty, max 20 chars | Class/grade (e.g., "Grade 3", "Class A") |
| mobile1 | String | Yes | Non-empty, valid phone format | Primary contact phone (SMS destination #1) |
| mobile2 | String | No | Valid phone format if provided | Secondary contact phone (SMS fallback #2) |
| totalTuition | Integer (cents/toman) | Yes | >= 0 | Total tuition amount for the term/year |
| currentDebt | Integer (cents/toman) | Yes | >= 0, <= totalTuition | Remaining debt (unpaid tuition) |
| isActive | Boolean | Yes | Default true | Whether the student is currently enrolled |
| createdAt | DateTime | Yes | Auto-set | Record creation timestamp |
| updatedAt | DateTime | Yes | Auto-update | Last modification timestamp |

### Field Notes

- **mobile1 (Primary):** The first SMS destination for entry/exit notifications. Must be present for every student.
- **mobile2 (Secondary/Fallback):** Used if SMS to mobile1 fails. Optional but strongly recommended.
- **totalTuition:** Full tuition amount expected from the student. Stored as an integer in the smallest currency unit (e.g., toman or cents) to avoid floating-point issues.
- **currentDebt:** The unpaid portion. Must satisfy `0 <= currentDebt <= totalTuition`. When a payment is recorded, `currentDebt` decreases accordingly.

---

## 2. Validation Rules

| Rule ID | Rule |
|---------|------|
| V-ST-01 | `fullName` and `fatherName` must not be empty or whitespace-only. |
| V-ST-02 | `mobile1` is mandatory and must be a valid phone number. |
| V-ST-03 | `mobile2`, if provided, must be a valid phone number and may equal `mobile1` (no hard restriction, but UI may warn). |
| V-ST-04 | `totalTuition` must be >= 0. |
| V-ST-05 | `currentDebt` must be >= 0 and <= `totalTuition`. Debt cannot exceed tuition. |
| V-ST-06 | `nationalId`, if provided, must be unique across all students. |
| V-ST-07 | `grade` must not be empty. |

---

## 3. Financial Scenarios

**SC-FN-01: Register a new student**
- Administrator enters identity data, both mobile numbers, and total tuition.
- `currentDebt` is initialized equal to `totalTuition` (full debt at registration).
- System validates all rules above before saving.

**SC-FN-02: Record a tuition payment**
- Administrator records a payment amount for a student.
- `currentDebt = max(0, currentDebt - paymentAmount)`.
- Payment cannot cause `currentDebt` to go negative (clamped at 0).
- Each payment is logged with date and amount (payment history).

**SC-FN-03: Adjust tuition total**
- Administrator can update `totalTuition` (e.g., discount applied).
- If new `totalTuition` < current `currentDebt`, `currentDebt` is clamped to the new `totalTuition`.

**SC-FN-04: View financial status**
- Student profile shows total tuition, current debt, and payment status (paid in full / partial / unpaid).
- Debtors list shows all students with `currentDebt > 0`.

---

## 4. SMS-Related Student Rules

| Rule ID | Rule |
|---------|------|
| V-SMS-01 | At least one of `mobile1` or `mobile2` should be present to enable SMS notifications. (`mobile1` is mandatory per V-ST-02.) |
| V-SMS-02 | Entry/exit SMS is sent to `mobile1` first; if it fails, fallback to `mobile2`. |

---

## 5. Acceptance Criteria (Phase 2.2)

- [ ] Student form captures: full name, father name, national ID (optional), grade, mobile 1, mobile 2 (optional).
- [ ] Financial fields: total tuition, current debt (initialized = total tuition).
- [ ] Validation enforces: debt >= 0, debt <= tuition, mobile1 mandatory.
- [ ] currentDebt auto-initializes to totalTuition on student creation.
- [ ] Payment recording reduces currentDebt (clamped at 0).
- [ ] Debtors list filters students with currentDebt > 0.
- [ ] nationalId uniqueness enforced.
