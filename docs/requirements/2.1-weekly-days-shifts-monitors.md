# Phase 2.1 — Weekly Days, Daily Shifts, and Assigned Monitors

## Goal
Define the scenarios, entities, and business rules for managing weekly days, daily shifts, and the monitor/supervisor assigned to each shift.

---

## 1. Weekly Days

### 1.1 Entity: WeekDay
A day of the week on which the school operates.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | Integer | Yes | Primary key |
| name | String | Yes | Day name (e.g., "Saturday", "Sunday", …) |
| code | String | Yes | Short code (e.g., "SAT", "SUN") |
| isSchoolDay | Boolean | Yes | Whether the school is open on this day |
| sortOrder | Integer | Yes | Position in the week (1–7) |

### 1.2 Scenarios

**SC-WD-01: Define school days**
- The administrator configures which days of the week are school days.
- Default: Saturday through Thursday are school days; Friday is a non-school day.
- Only school days can have shifts assigned.

**SC-WD-02: View all weekly days**
- Dashboard lists all 7 days with their school-day status.
- Non-school days are visually distinguished.

**SC-WD-03: Toggle school day status**
- Administrator can mark/unmark a day as a school day.
- If a day is unmarked, all shifts assigned to that day become inactive (not deleted).

---

## 2. Daily Shifts

### 2.1 Entity: Shift
A teaching/shift session tied to a specific day of the week.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | Integer | Yes | Primary key |
| dayId | Integer | Yes | Foreign key to WeekDay |
| name | String | Yes | Shift name (e.g., "Morning Shift", "Evening Shift") |
| startTime | Time | Yes | Shift start time (HH:mm) |
| endTime | Time | Yes | Shift end time (HH:mm) |
| monitorName | String | Yes | Name of the monitor/supervisor |
| isActive | Boolean | Yes | Whether the shift is currently active |
| classTimes | List<ClassTime> | Yes | One or more class times within this shift |

### 2.2 Entity: ClassTime
A specific class period within a shift (attendance is tracked per class time, not just per day).

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | Integer | Yes | Primary key |
| shiftId | Integer | Yes | Foreign key to Shift |
| name | String | Yes | Class time name (e.g., "First Period", "Second Period") |
| startTime | Time | Yes | Class time start (HH:mm) |
| endTime | Time | Yes | Class time end (HH:mm) |
| sortOrder | Integer | Yes | Order within the shift |

### 2.3 Scenarios

**SC-SH-01: Create a shift**
- Administrator selects a school day, enters shift name, start/end time, and monitor name.
- System validates: endTime > startTime; no overlapping shifts on the same day.

**SC-SH-02: Add class times to a shift**
- A shift must contain at least one class time.
- Multiple class times allowed (e.g., Period 1, Period 2, Period 3) within one shift.
- Class times must not overlap within the same shift.
- Class times must fall within the shift's start/end time.

**SC-SH-03: Activate/deactivate a shift**
- Administrator can toggle `isActive` on a shift.
- Inactive shifts do not appear in the attendance flow.
- Deactivating a shift does not delete its historical attendance records.

**SC-SH-04: Edit a shift**
- Administrator can change shift name, times, monitor, or class times.
- If shift times change, existing class times are re-validated against the new bounds.

**SC-SH-05: View shifts by day**
- Dashboard groups shifts under their respective week day.
- Only active shifts on school days are shown in the attendance flow.

**SC-SH-06: Prevent overlapping shifts**
- On the same day, two shifts cannot have overlapping time ranges.
- System rejects creation/update that would cause overlap.

---

## 3. Assigned Monitors

### 3.1 Rules

**SC-MN-01: Monitor assignment**
- Every shift must have exactly one monitor/supervisor assigned at creation.
- Monitor is stored as a free-text name (no separate staff module in Phase 1).

**SC-MN-02: Monitor display**
- The monitor name is displayed next to each shift on the dashboard.
- Attendance screen shows which monitor is responsible for the current shift/class time.

**SC-MN-03: Monitor change**
- Administrator can reassign a monitor to an existing shift.
- Change applies immediately to new attendance records; historical records keep the monitor name as it was at the time of recording.

---

## 4. Cross-Cutting Rules

| Rule | Description |
|------|-------------|
| R-01 | Shifts exist only on school days. |
| R-02 | A shift must have at least one class time. |
| R-03 | Attendance is recorded per student per class time (not just per day). |
| R-04 | Class times cannot overlap within a shift. |
| R-05 | Shifts cannot overlap on the same day. |
| R-06 | Deactivating a shift hides it from active flows but preserves history. |

---

## 5. Acceptance Criteria (Phase 2.1)

- [ ] Weekly days can be configured as school days / non-school days.
- [ ] Shifts can be created with day, name, start/end time, monitor, and active flag.
- [ ] Multiple class times can be added to a shift with start/end times and sort order.
- [ ] Overlapping shifts and class times are rejected by validation.
- [ ] Monitor name is stored and displayed per shift.
- [ ] Active/inactive toggle works for shifts.
