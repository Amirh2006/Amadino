# Phase 2.3 — Attendance Tracking per Class Time

## Goal
Establish the exact rules for recording attendance per student per class time (not just one daily entry), including date/timestamps, status values, duplicate prevention, and integration with shifts/class times.

---

## 1. Entity: Attendance

| Field | Type | Required | Constraints | Description |
|-------|------|----------|-------------|-------------|
| id | Integer | Yes | Primary key, auto-generated | Unique attendance record identifier |
| studentId | Integer | Yes | Foreign key to Student | The student being marked |
| classTimeId | Integer | Yes | Foreign key to ClassTime | The specific class period |
| shiftId | Integer | Yes | Foreign key to Shift | The shift (denormalized for quick filtering) |
| dayId | Integer | Yes | Foreign key to WeekDay | The day of the week (denormalized) |
| attendanceDate | Date | Yes | Not in the future | The date attendance is recorded |
| status | Enum | Yes | PRESENT / ABSENT / LATE | Attendance status |
| recordedAt | DateTime | Yes | Auto-set | Timestamp when the record was created |
| recordedBy | String | No | Max 100 chars | Name of the administrator who recorded it |

### Composite Unique Constraint
`(studentId, classTimeId, attendanceDate)` must be unique — a student can have only **one** attendance record for a given class time on a given date.

---

## 2. Core Rule: One Entry Per Class Time Per Day

**R-ATT-01:** Attendance is recorded per student **per class time**, not once per day.
- If a shift has 3 class times, a student may have up to 3 attendance records for that day (one per class time).
- Each class time is treated independently — a student can be PRESENT for Period 1 and ABSENT for Period 2 on the same day.

**R-ATT-02:** A student can only be marked for class times belonging to a shift that is active on a school day.
- The class time's shift must be `isActive = true`.
- The class time's shift's day must be `isSchoolDay = true`.

**R-ATT-03:** Attendance can only be recorded for the current date or past dates — never future dates.

---

## 3. Attendance Status Values

| Value | Meaning |
|-------|---------|
| PRESENT | Student attended the class time. |
| ABSENT | Student did not attend the class time. |
| LATE | Student arrived late to the class time. |

---

## 4. Scenarios

**SC-ATT-01: Open attendance screen for a class time**
- Administrator selects a day, then an active shift, then a class time within that shift.
- System displays all students assigned to that shift (see Phase 6 for student-shift assignment).
- Each student shows: name, current status (if already recorded for today), and a PRESENT / ABSENT / LATE selector.

**SC-ATT-02: Mark attendance for multiple students**
- Administrator sets status for each student and saves.
- System creates one Attendance record per student for `(studentId, classTimeId, attendanceDate = today)`.
- Records are created only for students whose status was changed (or all students if none exist yet).

**SC-ATT-03: Edit an existing attendance record**
- If a record already exists for `(studentId, classTimeId, today)`, editing updates that record's `status` and `recordedAt`.
- No duplicate record is created.

**SC-ATT-04: View attendance history**
- Filterable by student, class time, shift, day, date range, and status.
- Shows date, class time name, shift name, monitor name, and status for each record.

---

## 5. Duplicate Prevention Rules

| Rule ID | Rule |
|---------|------|
| DP-01 | `(studentId, classTimeId, attendanceDate)` is a unique constraint in the database. |
| DP-02 | Before inserting, the system checks if a record already exists for the same student, class time, and date. |
| DP-03 | If a record exists, the save operation performs an **update** (upsert), never a second insert. |
| DP-04 | The UI disables duplicate submission: once attendance is saved for a class time/day, re-saving triggers an update, not new rows. |

---

## 6. Integration With Shifts and Class Times

- Attendance is scoped to a specific `ClassTime`, which belongs to a `Shift`, which belongs to a `WeekDay`.
- The `shiftId` and `dayId` are stored on each Attendance record (denormalized) so reports can be filtered by shift or day without joining through ClassTime.
- Only students assigned to the shift (Phase 6 filtering) appear in the attendance entry screen for that class time.

---

## 7. Acceptance Criteria (Phase 2.3)

- [ ] Attendance record has studentId, classTimeId, shiftId, dayId, attendanceDate, status, recordedAt.
- [ ] Status enum supports PRESENT / ABSENT / LATE.
- [ ] Composite unique constraint on (studentId, classTimeId, attendanceDate).
- [ ] Attendance can only be recorded for active shifts on school days.
- [ ] Future dates are rejected.
- [ ] Re-saving attendance for an existing (student, class time, date) updates rather than duplicates.
- [ ] One class time = one attendance record per student per day (independent across class times).
